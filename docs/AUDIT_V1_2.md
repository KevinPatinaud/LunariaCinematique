# Audit et correctifs · Lunaria Cinematic Studio V1.2

Livraison issue de l’archive V1.1 fournie dans cette conversation. Le périmètre couvre l’état du document, les fichiers, la bibliothèque, l’édition de scène, la lecture et le lecteur Godot livré en sources. Il ne couvre pas le reste du jeu ni une autre branche de Lunaria Studio.

**Cette liste recense les anomalies et cas limites identifiés pendant cet audit, pas la preuve de l’absence de tout autre bug.** Les lignes qui relèvent d’une revue de code native ou d’un durcissement ne sont pas présentées comme des reproductions sous Windows. Les changements sont intégrés aux sources et non limités à des recommandations.

## Lecture des preuves

**N** : tests TypeScript compilés puis exécutés par Node, y compris des opérations réelles dans des répertoires temporaires. **I01–I35** : scénarios d’interaction dans Chromium avec le vrai code React, un pont Electron simulé et les conditions précises du [rapport de validation](TEST_REPORT_V1_2.md). **Revue** : inspection/correction de source sans exécution de cette plateforme.

**P1** : risque de perte/écrasement ou d’incohérence de données. **P2** : fonctionnement ou rendu incorrect. **P3** : outillage. Ce sont des priorités de traitement, pas des scores de sécurité.

## Compatibilité et données

Le contrat reste **schemaVersion: 1**. Les chemins `library://` ne sont pas renommés. Les cinématiques V1/V1.1 valides peuvent être ouvertes sans migration et les cinq images d’exemple restent inchangées. La bibliothèque complète n’est pas ajoutée au projet ; enregistrer une cinématique ne copie pas ses images.

La validation est plus stricte pour les types de ressources : un ancien brouillon utilisant un son comme décor est maintenant refusé, pas automatiquement converti. Un texte très long reste enregistré intégralement ; l’avertissement de débordement doit être résolu en agrandissant la bulle, réduisant raisonnablement la police ou répartissant le texte en répliques. Le studio ne coupe pas le texte à ta place.

La détection d’une modification externe compare le fichier juste avant l’écriture. Ce n’est pas un verrou distribué contre un autre programme qui écrirait exactement pendant le remplacement. De même, `.bak` et la récupération locale ne remplacent pas Git ni une sauvegarde du disque.

## Ce qui reste à vérifier

Exécution Electron sous Windows, fenêtres natives, comportement réel de l’antivirus lors des remplacements, surveillance native, gestion de la mise à l’échelle de Windows, débit/mémoire avec la bibliothèque complète, build de production avec les dépendances déclarées, puis exécution Godot et Android. Les points concernés sont signalés dans le registre.

Le rendu typographique React/Godot n’est pas garanti identique : la police du jeu doit être configurée et vérifiée. Les animations de marche, timeline multipiste, branches narratives et export vidéo restent hors du périmètre fonctionnel V1, pas des fonctionnalités implicitement corrigées.
